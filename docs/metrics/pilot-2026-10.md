## How it was measured

- One machine, 4 cores, `CARGO_BUILD_JOBS=2`, a shared target directory, with no incremental
  compilation and no debug info, as CI builds.
- Each build figure is the median of three runs, each run after `touch`-ing one file. The three
  runs are in brackets. Another session building in the same target directory may have overlapped
  some runs, so a difference inside the bracketed ranges is noise.
- "Before" is `main` at f90600d, whose crates are identical to those #727 started from.
- A reporting handler is `revenue.rs` (in `pos-cloud/src/http.rs` before the pilot), and a
  non-reporting handler is one that stays in `pos-cloud/src/http.rs`.

## Findings

1. **A crate split moves adapter impls with the traits.** `pos-cloud` implemented its store traits
   for `store-postgres`'s types (`AdminStore`, `ApiKeyStore`, `ApiKeyAdminStore`, `AuditStore`,
   `RollupStore`). Rust allows an impl of a trait for another crate's type only in the trait's own
   crate. So when the traits moved, about 670 lines of impls moved with them. As a result, both
   `pos-cloud-api` and `pos-cloud-reports` depend on `store-postgres`, as `pos-cloud` already did.
   The alternatives were newtype wrappers in `pos-cloud`, which means edits wherever the stores
   are composed, or `store-postgres` implementing the traits, which reverses the dependency.
2. **`affected` widens.** A reporting-only change ran one crate before and runs two after: the
   reports crate, plus `pos-cloud`, which depends on it.
3. **The route tests stay in `pos-cloud`.**
   - The report routes' HTTP tests drive the full router, so they remain in
     `pos-cloud/tests/cloud.rs`.
   - `pos-cloud-reports`' own 38 tests cover the fold, the projection and the CSV files.
   - Checking a report route still means building `pos-cloud`'s tests: 110.6 s against 3.6 s for
     the crate's own.
4. **The longest functions are the least tested.**
   - The longest, `pos-cloud/src/main.rs::run` (1,168 lines), has no tests: it is the binary's
     startup.
   - The fourth longest, `store-postgres` `PostgresStore::migrate` (347 lines), is tested only
     against a real PostgreSQL. That needs Docker, which the pilot's machine did not have.
   - Both were left unsplit, because a split needs its tests run first and a mutation check.
5. **Long-function exemptions were reviewed, not obeyed.** Every candidate carried a reasoned
   `#[expect(clippy::too_many_lines)]`.
   - **Overridden, three:** the reasons of the three split were met another way.
     - `session_from_config`'s own reason described independent branches, which split cleanly.
     - `register`'s entries were already grouped by node.
     - `admin_schedule_release`'s reason, that no write may move above a check, is now visible in
       the handler's own lines. They read as the steps in order, and a refusal stops at the first.
   - **Kept, three, because the reasons hold:**
     - `store-sqlite` `writer::run`: a dispatch table whose arms already forward;
     - `pos-edge` `domain_router` and `pos-cloud` `router`: route tables;
     - `pos-edge` `compose`: its parts would each need most of its locals.
6. **What a move-only change also needs.** Each needed some of the following, beyond the moves:
   - **The size ratchet keys files and functions by path,** so a moved file or function reads as
     new. #728 and #730 each carried `size-baseline: grow` in their bodies for that.
   - **Doc comments on documented handlers are published text.** utoipa copies them into the
     OpenAPI document. Correcting a relative link in one changed the document, and the snapshot
     test caught it.
   - **Moved files leave links behind.** Nine links in six ADRs pointed at files that moved. Only
     their targets were changed, in commits of their own.
   - **Blame needs a follow-up commit.** `main` is squash-merged, so a move is listed in
     `.git-blame-ignore-revs` by its squashed commit, in the pull request after it.
7. **Pull requests over the 400-line guideline.** All four exceeded it. #727 and #728 were move-only
   by `git diff --color-moved`, which is ADR-0170's allowance:
   - #727: 631 of 742 added lines were moves;
   - #728: 863 of 970.

   #730 carried three small edits before its move (883 of 1,151 added lines moved). #732 is five
   restructures, not moves.

## What this says for gate 1

These are the facts gate 1 is decided on. They are not a recommendation.

**What changed:**
- A change to a report is now made in one crate. It means reading 3,175 lines instead of 42,386,
  and the largest file to open is 1,487 lines instead of 38,555.
- That crate builds in 2.4 s and builds its tests in 3.6 s.

**What did not change:**
- Building `pos-cloud`, which a report change still requires, takes about 81 s. That is 88.5 s
  before: the two sets of runs do not overlap, but this pilot does not attribute the difference,
  because the earlier runs may have shared the machine with other builds.
- Its test build takes about 110 s, against 117.9 s before; those runs overlap.
- A non-reporting change to `pos-cloud` builds in the same time as before.

**What the split costs:**
- A reporting change runs one more crate in CI.
- Its route tests stay in `pos-cloud`.
- The new crates depend on `store-postgres` because the adapter impls moved with their traits.

**The pilot's limits:**
- Nothing published changed, and every test that existed before still runs.
- The two longest functions in the codebase are untested or tested only against PostgreSQL. The
  pilot did not split them.

Phases 5–7 would apply the same steps to the remaining business areas: nine cloud and five edge
crates under ADR-0170 decision 4.

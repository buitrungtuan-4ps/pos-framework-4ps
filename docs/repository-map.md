# Repository map — to do X, edit these files

**Status** Accepted · **Owner** @maintainers-architecture · **Last reviewed** 2026-10-21
· [ADR-0170](adr/0170-repository-layout-code-naming-and-size-rules.md) · [docs index](README.md)

One table per kind of change. Each row is a file you edit or regenerate, and the gate that fails
when you forget it. Where one change touches several places, the area's heading says how many.
For a route, the handler's OpenAPI annotation is the one description
([ADR-0177](adr/0177-openapi-is-the-route-map.md)): the document, the route map and the
front end's generated types are regenerated from it, and a test fails on a route without one.
[`generated/route-map.md`](generated/route-map.md) lists every route with its handler's file.

Every path in backticks below names a file or directory that exists, which
`xtask repo-map` checks; a path with `<…>` or `*` names the directory it starts in.

How to read the **Checked by** column:

- **`xtask <name>`** is `cargo run -q -p xtask -- <name>`. It runs in the `rules` job of
  [`pr.yml`](../.github/workflows/pr.yml), and most also run in `just preflight`.
- **A test name** is a Rust test that fails on drift. You regenerate its file with
  `POS_UPDATE_SNAPSHOTS=1` and the test command given in the row (`just snapshot` does pos-proto and
  pos-core).
- **`ui build`** and **`dashboard build`** are `pnpm build`. It typechecks, runs the i18n lint and
  parity, contrast and step-budget scripts, and in `dashboard/` the vitest suite. The same jobs run
  **`pnpm lint`** first: ESLint's size rules and their baseline ([ADR-0172](adr/0172-eslint-checks-the-front-ends.md)).
- **replay** and **console-replay** are the Playwright jobs.

Every change also needs a `changes/<topic>.md` file ([`changes/README.md`](../changes/README.md),
checked by `xtask changelog --check` in `docs-gate`). It also needs the spec section it changes,
usually in [`pos-spec.md`](pos-spec.md). A citation of an ADR must name one that exists, which
`xtask gen-docs --check` enforces. To find the code an ADR governs, run
`cargo xtask gen-docs --adr-citations ADR-NNNN`.

## Domain rule, calculation or state machine

| Step | Files | Checked by |
|---|---|---|
| The rule | `crates/pos-core/src/<area>.rs`, for example `billing.rs` (`decide_bill`) or `decision.rs` | `test`. Unit tests sit in the same file and use no I/O |
| A state machine's table | `crates/pos-core/src/machines.rs` → [`state-machines.md`](state-machines.md) (generated) | `POS_UPDATE_SNAPSHOTS=1 cargo test -p pos-core` |
| Purity | No I/O, clock or RNG dependency; `ClockSource` and `IdGenerator` ports instead | `xtask deps-rule` ([`tools/backbone-allowlist.toml`](../tools/backbone-allowlist.toml)), clippy backbone (no `unwrap`), `xtask vendor-neutral-core` |
| Where the edge applies it | `crates/pos-edge-app/src/app/<area>/`, the load → decide → apply → publish layer (`Edge` in `app/mod.rs`) | `crates/pos-edge/tests/<area>.rs` |
| The behaviour | [`pos-spec.md`](pos-spec.md), the section for the area | review |

A change to how money, tax or receipt numbering works needs an ADR first (AGENTS.md §7).

## Screen

**Till** (`ui/`). One registry: `SCREENS` in `ui/src/state/screens.ts` is the list the router is built
from, and `COMPONENTS` in `ui/src/App.tsx` maps each screen's id to its component, so one without the
other does not compile. `cargo xtask new screen --app ui <id> --path <path> --title <English>
--title-vi <Vietnamese>` writes the screen and its lines in each file below except the task budget.
Each catalogue in `ui/src/i18n/` other than English needs its `--title-<locale>`; the generator
never writes a string nobody gave it.

| Step | Files | Checked by |
|---|---|---|
| Screen | `ui/src/screens/<Screen>.tsx` | `ui build`, `pnpm lint` |
| Route | its entry in `SCREENS` (`ui/src/state/screens.ts`) and in `COMPONENTS` (`ui/src/App.tsx`) | `ui build` (the type check, and the step budget reads both); replay (every route opens its screen) |
| Task budget | `TASKS` in `ui/scripts/step-tasks.mjs` | `ui build` |
| Strings | `ui/src/i18n/en.json`, `vi.json` | `ui build` (i18n lint and parity) |
| Flow | `ui/tests/replay.spec.mjs` | replay, which also requires every flow to be replayed or to say why not |

**Console** (`dashboard/`). Already one registry: `SCREENS` in `dashboard/src/state/screens.ts`
feeds the router, nav, breadcrumbs and command palette ([ADR-0060](adr/0060-cloud-back-office-dashboard.md)).
`cargo xtask new screen --app dashboard <id> --path <path> --title <English> --title-vi <Vietnamese>
--scope <tenant|store|console> --icon <name> --nav-group <group>` writes every row below. The scope,
the icon and the nav group are design choices, so each is required: the icon must already be in
`ICON_NAMES`, and a group that holds six screens, the ceiling, is refused. The titles follow the
till's rule. Rules for any screen are in [`ui-ux.md`](ui-ux.md).

| Step | Files | Checked by |
|---|---|---|
| Screen | `dashboard/src/screens/<Screen>.tsx` | `pnpm build`, `pnpm lint` |
| Route and nav | its entry in `SCREENS` and its id in its group in `NAV_GROUPS` (`dashboard/src/state/screens.ts`); its `lazy()` block and `COMPONENTS` entry (`dashboard/src/App.tsx`) | `pnpm build` (the type check); the nav-groups, icons and dev-proxy tests |
| Strings | `dashboard/src/i18n/en.json`, `vi.json`, the key `nav.<id>` | `pnpm build` (i18n lint and parity) |
| Test | `dashboard/tests/<kebab-id>.test.tsx`, that the screen draws its title | `pnpm test` |

## New crate

`cargo xtask new crate <name> --layer <layer> --purpose <one line> [--adr <number>]...` writes the
first three rows: the `members` line, the manifest with its card (owners from `CODEOWNERS`), the
README and the crate root. Add `--dry-run` to print them instead. It never overwrites a file
([ADR-0176](adr/0176-the-adapter-and-country-standard.md)).

| Step | Files | Checked by |
|---|---|---|
| Workspace | `members` in the root `Cargo.toml` | build |
| Contract card | `[package.metadata.pos]` in its `Cargo.toml`: `layer`, `purpose`, `adrs`, `owners` | `xtask crates` |
| README | `README.md` with the six headings, as `crates/pos-core/README.md` has them. Its Layer, Owners, Depends on and Used by lines are checked | `xtask crates` |
| Its neighbours | the Depends on or Used by line in the README of every workspace crate it depends on or that depends on it | `xtask crates` |
| Graph | [`generated/crate-graph.md`](generated/crate-graph.md), regenerated by `cargo xtask gen-docs` | `xtask gen-docs --check` |
| Owners | the card's `owners`. [`generated/codeowners-crates.txt`](generated/codeowners-crates.txt), regenerated by `cargo xtask gen-docs`, holds the line `CODEOWNERS` would have for the crate; a person adds it there. A crate line already in `CODEOWNERS` must match it | `xtask gen-docs --check` |

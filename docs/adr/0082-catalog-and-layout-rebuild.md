# ADR-0082 — Catalog & Layout rebuild: split the monolith into kit sub-screens, make Layout a visual grid

**Status** Accepted · **Owner** @maintainers-cloud · **Last reviewed** 2026-08-28
**Relates to** [ADR-0066](0066-cloud-catalog.md) (the catalog authoring model these screens edit) · the F2 CRUD kit (`dashboard/src/components/kit.tsx`) and API foundation these consume · [ADR-0020](0020-i18n-runtime.md) (the i18n runtime + no-hardcoded-strings gate every new string obeys) · [ADR-0074](0074-localization-and-tax.md) (store locale/currency, the source a price field wants) · `docs/cloud-admin-ux-plan.md` (Track F3)

**Context.** Catalog and Layout are the **last two** dashboard master-data screens still pre-F2: 23 others use the F2 kit, but `Catalog.tsx` (1,898 lines, nine entities in one scroll) and `Layout.tsx` (710 lines) hand-roll every table and every inline edit, with no `DataTable`, no `Drawer`, no `ConfirmDialog`, and no search. Catalog is a maintainability problem and hard to navigate; Layout edits button placement as hand-typed integer `sort`/`column`/`row` fields with no visual grid, no collision feedback, and no way to copy a channel's layout to another. Both are the target of Track F3, sequenced last in Track F because it consumes everything F2 built. The **backend CRUD already exists** (Phase 2a) — F3 is a frontend rebuild, no `/admin` route, `pos-proto`, or migration change.

**Decision.** Rebuild both screens on the F2 kit, additively and behaviour-preserving (the backend contract is untouched; each entity's existing create/edit/archive semantics are kept).

1. **Catalog → tabbed sub-screens under one `/catalog` route.** A `CatalogShell` with a tab bar renders five kit-based sub-components — **Items**, **Taxonomy** (item categories + subcategories), **Tax classes**, **Modifiers**, and **Menus** (menus + sections + placements + publish). One route, one nav entry, one breadcrumb (no nav bloat); the split is by component file under `dashboard/src/screens/catalog/`, sharing a small `shared.tsx` (channel labels, price-sheet/translation helpers, status label). Each sub-screen uses `DataTable` (client search + sort), a `Drawer` for edit, `ConfirmDialog` (typed-name for the few destructive actions), `StatusBadge` for active/archived, and `TechnicalDetails` for the ULIDs the monolith prints inline. To keep the build green through the migration, the sub-components are built first (compiling, unrouted); the final catalog slice swaps `/catalog` to the shell and deletes the monolith.

2. **Currency-aware price fields + bulk price editing.** A new `MoneyField` (in `components/ui.tsx`) edits an amount in a currency's minor units with locale grouping shown as the operator types, storing the integer minor unit exactly as today (`amount_minor`). The placement editor's free-text currency becomes a picker over `api.listCountries()` currency codes. The Menus sub-screen gains **bulk price editing** — set one channel's price across selected items in a section at once. **Deliberately not built:** a backend read of the store's *published* currency to prefill the field. There is no `GET` for a store's locale today (`StoreSettings` only publishes it, ADR-0074), so the field's currency is chosen explicitly from the country list; wiring the field to the store's actual published currency is a flagged follow-up (a small `/admin` locale read).

3. **Layout → a visual grid.** Per channel, buttons render on a device-shaped preview at their `(column, row)`; a client-side **collision check** flags two enabled buttons sharing a cell before save; **copy-between-channels** clones a channel's buttons to another (N× `setLayoutButton`); and ordering uses the kit's `ReorderList` — F3 is its first consumer — with **pointer drag layered on top of its existing keyboard up/down**, the buttons staying as the accessible fallback (exactly what `ReorderList`'s own docstring anticipated). The display-taxonomy cards move onto the kit like the rest. Publishing stays where it is — the Menus sub-screen compiles and publishes both the priced `menu` node and the `layout` node together; Layout only edits buttons.

**Deliberately deferred (flagged, not silently dropped).**

- **Store-currency prefill.** The price field's currency is picked from the country list, not read from the store's published locale (no such read exists yet). A small `/admin` locale read to prefill it is the follow-up.
- **Full grid pointer-drag polish.** Pointer drag lands on `ReorderList` (flat ordering) and as click-to-place on the grid; a fully free-form drag-and-drop with live cell snapping and animated reflow is a polish pass, and the keyboard/button controls remain the guaranteed path. If the pointer-drag-on-grid interaction proves fiddly, it ships behind the accessible controls rather than blocking the track.
- **Shared web-kit extraction (Fork A).** Extracting the kit into a package shared with `ui/` waits until F3 stabilises, unchanged from the roadmap.

**Consequences.**

- Frontend-only and behaviour-preserving: no `/admin` route, `pos-proto`, dependency, permission, or migration change. Every new string goes through `t()` into both `en.json` and `vi.json` (ADR-0020); the no-hardcoded-strings and WCAG-AA gates run in `pnpm build`; every dashboard PR carries a `CHANGELOG` entry (the repo's dashboard changelog gate).
- Catalog becomes five focused, searchable, kit-consistent sub-screens instead of one 1,898-line scroll, and Layout becomes a visual editor — the maintainability and usability wins F3 is for — while the authored data model (ADR-0066) and its publish path are untouched.
- Catalog and Layout carry **T2** commercial data (prices, per-channel placement) worked in the console, not reproduced externally; no T1 (customer/employee) field is involved. The bulk price editor writes the same audited `setPlacement` path as today.
